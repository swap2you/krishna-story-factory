# Master Program Scope — Remaining Releases Combined

This is one program with internal milestones. Cursor works sequentially but does not require a new user prompt between milestones.

## M1 — Baseline, source intake, and visible Bhāva shell

**Purpose:** make the platform understandable before adding content volume.

- Reconcile current routes/navigation with the four pillars: Library, Knowledge, Learning, Prabhupāda Vāṇī.
- Build/refine a consistent public home and top-level navigation using Board B tokens: deep navy, muted gold, ivory/cream, restrained saffron/lotus/sage, calm editorial rhythm, and no cartoon dashboard clutter.
- Public Library shelves must distinguish **Available** from **Planned**. A planned shelf cannot look clickable/published when it has no real content.
- Add honest, useful public entry surfaces for Knowledge, Learning, and Prabhupāda Vāṇī. They must explain what is available now and lead only to approved material.
- Preserve story routes, public cap 25, private routes, health/version behavior, and SEO boundaries.
- Import the 12 PDF inventory as private intake metadata only. Reconcile the stale "missing PDFs" text without committing originals, OCR derivatives, databases, or ad-hoc SQL.
- Validate the local development-mode guard and correct it if required.

**Visible result:** the home and navigation clearly show the full Bhāva product, but without pretending unavailable collections exist.

## M2 — Knowledge vertical: R01–R04 combined

**Purpose:** turn the private foundation into a repeatable, reviewable Knowledge system with a real public pilot only where source gates are satisfied.

- Complete source dossier/claims/rights/review workflows and private Studio status clarity.
- Establish one approved golden record and four confirmation records using only source-adequate materials. If the Nṛsiṁha candidate cannot be validated, do not fake it; select another adequate candidate documented in the source ledger.
- Freeze Page Template V1: semantic text, Devanāgarī/IAST Unicode behavior, four lenses, focus mode, source/review panel, correction path, responsive Board B layout, and study-neutral PDF/DOCX exports.
- Convert the 12 supplied PDFs into private source inventory entries. For the two image-only PDFs, record OCR as pending unless the repository’s supported OCR workflow runs; preserve originals unchanged.
- Create a 25-record batch manifest and build all records that actually clear source/review gates. Blocked records remain private and visibly labelled in Studio; they must never create fake public pages.
- Build the 50-item private-draft factory: deterministic queue, idempotency, resumability, per-stage retry, duplicate detection, template/prompt ledger, cost counters, Studio progress, dry-run evidence. It has zero approval, merge, deploy, or publication authority.

**Visible result:** Knowledge has a genuine landing/catalog and approved pages; every listed item is real, sourced, and consistent. Studio gives an honest private view of blocked/draft/review states.

## M3 — Learning resources and publication packages: R05–R06 combined

**Purpose:** derive useful education and publishing outputs from approved canonical Knowledge records rather than creating disconnected worksheets.

- Add Learning pathways for children/youth, families, Sunday School, teachers, preachers, Gurukula/homeschool, and festival use.
- Create original derivative contract: learning objective, audience/age profile, canonical record/version, source lineage, review state, answer-key relationship, asset provenance, and export manifest.
- Build approved printable/teacher-resource templates: lesson plan, teacher guide, activity/worksheet, assessment/quiz, answer key, and family practice sheet. Use only approved canonical records as inputs.
- Build Publishing Studio handoff packages for approved Bhāva-original works: PDF/EPUB/print-oriented manifest, cover/asset provenance, author/publisher metadata, and versioning. Do not put commercial authoring internals or private source PDFs in the platform repo.
- Apply the approved identity for original publications where such metadata is truly needed: Svarna Gauranga Das; Dauji Publication; A Bhāva Project publication; Harrisburg, Pennsylvania, USA; svarnagaurangdas@gmail.com; no phone number.

**Visible result:** Learning is a real product area with usable, polished resources—not a static future tab.

## M4 — Prabhupāda Vāṇī, audio/podcast pilot, and controlled scheduler: R07–R08 combined

**Purpose:** create a trustworthy source-led Vāṇī experience without impersonation or uncontrolled automation.

- Build Prabhupāda Vāṇī collection and record model: verified quotation/teaching, exact source context, topic, audience depth, reviewer state, correction route, and related approved records.
- No fabricated quotes, decontextualized quote cards, AI impersonation, or generated first-person Prabhupāda dialogue.
- Pilot neutral educator-host audio discussions only from approved source/transcript packs, with clear AI-educational disclosure, source notes, timecodes, transcript-equivalence review, and listening QA. Do not clone a voice.
- Build scheduler controls only for private-draft work: schedule status, queue choice, idempotency, retries, cost limits, dry-run, logs, disable switch, and approval boundaries. It cannot approve, merge, deploy, or publish.
- Existing Story scheduler remains unchanged except for regression validation; never trigger a story generation as part of this program.

**Visible result:** Vāṇī is a trustworthy, context-rich study surface; audio is clearly labeled and only present when source/rights gates pass.

## M5 — 3D/motion research readiness: R09

**Purpose:** establish a governed experimental lane without destabilizing the public platform.

- Create an offline, separate 3D/motion-lab contract: source/asset rights, reproducibility, hardware/time/cost reporting, character/iconographic review, artifact manifests, and no automatic public site integration.
- Add no permanent mascot, public nav item, autoplay, cursor-follow effect, or runtime 3D dependency to the live site.
- Use motion only where it supports learning; honor reduced-motion preferences.

**Visible result:** no public 3D gimmick. The output is a decision-ready, reproducible research lane.

## Explicitly out of scope

- Rebuilding accepted Stories 001–025 or exposing 026+.
- Public forum, accounts, child profiles, behavioral tracking, comments, uploads, or personalized recommendations.
- Framework migration, database replacement, broad dependency upgrades, or copying external PDF content into public files.
- Any production release of a record that lacks source, rights, review, export, privacy, or security proof.
